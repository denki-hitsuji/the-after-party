# draft-articles

文字起こしテキストから After Party の記事群を生成する。必ずフェーズ1（プランニング）→ユーザー承認 → フェーズ2（生成）の順で進む。

## 事前確認

実行前に以下をユーザーに確認する。推定できる項目は候補を提示して承認を求める。

| 項目 | 例 |
|------|-----|
| 文字起こしファイルパス | `content/posts/yurie-and-mercy/文字起こし.md` |
| アーティストslug（ディレクトリ名） | `yurie-and-mercy` |
| 画像ファイル名プレフィックス | `ym`（`ym01.png` のように連番で使う） |
| `musician` | `yurie♪&マーシー` |
| `band` | `yurie♪&マーシー` |
| `donate_button_id` | Stripeボタンのid |
| `date` | インタビュー日（ISO8601 JST 例: `2026-04-07T21:25:00+09:00`） |
| `draft` | `true` or `false` |
| 既存記事数（追記の場合） | `6`（次は07から始める） |

---

## フェーズ1：プランニング

文字起こしを全文読んだうえで、以下の方針で分割案を作成する。

### 基本方針：各駅停車

ライブ感を最優先する。会話の流れをそのまま生かし、記事数は多くなって構わない。
話題の切れ目（セクション見出し・場の雰囲気の変化）を分割の目安にする。

### 省略・要約する箇所

以下は省略または要点のみ掲載し、詳細は割愛する。省略した場合は本文中に記載しない（痕跡を残さない）。

- インタビュイーがオフレコを望んだ発言
- 専門性が高く読者にはわからない技術的会話
- 出演者の知人に関する話など、読者が知り得ない固有情報
- 酔いが回って会話が断片的または冗長になった部分

### プランの提示形式

```
全N話構成（既存Mから始める場合は第M+1話〜第N話）

第1話：「タイトル」
  → 内容の概要（1行）
  → 省略箇所があれば理由とともに明記

第2話：「タイトル」
  → ...
```

**ユーザーの承認を得てから必ずフェーズ2に進む。**

---

## フェーズ2：記事生成

承認が得られたら、全記事を1本ずつ順番に生成する。

### ファイル構成

```
content/posts/{slug}/{NN}/index.md
content/posts/{slug}/{NN}/{prefix}{NN}.png  ← ユーザーが配置済みの前提
```

`{NN}` はゼロ埋め2桁（`01`, `02`, ...）。

### front matter テンプレート

```yaml
---
title: "{musician} ｜ 第{N}話：「{タイトル}」"
date: {date}
musician: "{musician}"
band: "{band}"
donate_button_id: "{donate_button_id}"
draft: {draft}
---
```

### 本文構成

1. front matter 直後に画像を1枚:
   ```markdown
   ![{musician}](./{prefix}{NN}.png)
   ```

2. 会話はすべて `**話者：**` 形式で記述:
   ```markdown
   **さとレックス（以下さとレ）：** ...

   **{musician}：** ...
   ```

3. イントロ相当のまとまり（冒頭2〜3発言程度）の直後に `<!--more-->` を挿入。

4. 話題の切れ目ごとに `---` で区切る。

5. 最終話を除く各記事の末尾に次の話へのリンク（末尾スラッシュ必須）:
   ```markdown
   *[第{N+1}話につづく](../{NN+1}/)*
   ```

6. 最終話の末尾にはリンクを付けない。

### 生成後の検証

全記事の生成が完了したら `/check-links` を実行し、末尾スラッシュ違反がないことを確認する。
